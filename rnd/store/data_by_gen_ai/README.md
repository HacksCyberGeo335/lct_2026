# Карточки строительных работ

[construction_work_cards.json](construction_work_cards.json) — справочник строительных работ с экспертной разметкой для анализа стройплощадки по наружной камере. Для каждой строки исходного перечня указаны категория процесса, наблюдаемость, техника, положительные визуальные признаки и известные технологические зависимости.

Файл помогает выбирать работы, которые можно наблюдать, и интерпретировать возможные признаки их выполнения. В нем нет результатов распознавания конкретных кадров, фактического статуса стройки, календарных дат и длительностей.

## Состав файла

Показатели рассчитаны для текущего содержимого JSON со `schema_version: "1.0"`.

| Показатель | Значение |
| --- | ---: |
| Всего карточек | 377 |
| Отдельные пункты — `ITEM` | 329 |
| Агрегирующие разделы — `AGGREGATE` | 48 |
| Различные исходные названия, с учетом пробелов | 360 |
| Категории `macro_stage`, включая `UNKNOWN` | 36 |
| Направленные зависимости между карточками | 36 |
| Карточки с `UNKNOWN` в обоих полях зависимостей | 317 |
| Карточки с нулевой наблюдаемостью | 60 |
| Справочные внешние источники | 7 |

`ITEM` означает отдельный пункт перечня, но не гарантирует, что это одна неделимая операция. Например, название может объединять устройство основания и монтаж оборудования. `AGGREGATE` объединяет несколько работ; при подсчете операций его следует учитывать отдельно от входящих в раздел пунктов.

## Происхождение данных

Источник — [Сводный перечень строительных работ](<data_src/7.ДГП_датасеты/Сводный перечень строительных работ_ЛТЦ.xlsx>), лист `Лист1`, ячейки `B4:B380`.

- На каждую непустую строку создана одна карточка. Названия сохранены дословно, включая опечатки, пробелы и переводы строк.
- Идентификатор отражает номер строки Excel: `work_081` соответствует ячейке `B81`. При перестановке строк в новой версии Excel такой идентификатор не гарантирует сохранение смысла.
- Повторяющиеся названия сохранены в своем контексте. Для обращения к карточке используйте `id`, а не только `work_name`.
- Столбец A не использован для идентификаторов: часть кодов Excel хранит как числа с форматом даты.
- Отметки применимости к типам объектов из столбцов C–K не перенесены в отдельное поле карточки.
- Путь и SHA-256 исходного файла записаны в корневом объекте `source` для проверки версии источника.

В Excel нет оценок наблюдаемости, перечней техники и графа зависимостей. Эти сведения сформированы как экспертные предположения (`EXPERT_INFERENCE`) по названиям и контексту работ. Справочные ссылки подтверждают отдельные общие технологические принципы, но не всю разметку и не параметры конкретного объекта.

## Структура JSON

Корень файла — объект, а массив карточек находится в поле `cards`. Кодировка — UTF-8.

| Поле верхнего уровня | Содержимое |
| --- | --- |
| `schema_version` | Версия формата, строка `"1.0"`. |
| `source` | Путь и хеш Excel, лист, столбец названий, диапазон строк и число карточек. |
| `annotation_policy` | Правила разметки: допущения о камере, трактовка оценок, техники, признаков и зависимостей. |
| `macro_stage_definitions` | Словарь кодов категорий и их русских описаний. |
| `references` | Массив источников с полями `id`, `title`, `url`, `supports`. |
| `cards` | Массив из 377 карточек в порядке строк исходной таблицы. |

## Поля карточки

| Поле | Тип | Значение |
| --- | --- | --- |
| `id` | Строка | Уникальный идентификатор внутри файла, например `work_081`. |
| `source` | Объект | Поля `sheet`, `row`, `cell`, `context` связывают карточку с исходной строкой. |
| `work_name` | Строка | Неизмененное название из Excel. |
| `row_kind` | Строка | `ITEM` — отдельный пункт; `AGGREGATE` — общий раздел. |
| `macro_stage` | Строка | Код категории из `macro_stage_definitions`, например `ROAD_BASE`, `FACADE`, `INTERNAL_UTILITIES`. |
| `external_camera_observability` | Число от 0 до 1 | Экспертная оценка возможности распознать процесс или его непосредственный результат наружной камерой. |
| `required_equipment` | Массив строк или `"UNKNOWN"` | Обязательные функциональные типы техники либо неопределенность состава. |
| `optional_equipment` | Массив строк | Возможная техника, зависящая от метода и условий. |
| `positive_visual_signs` | Массив строк | Наблюдаемые действия или непосредственные результаты, поддерживающие гипотезу о выполнении работы. |
| `observability_note` | Строка | Ограничения видимости и интерпретации; может быть пустой. |
| `predecessor` | Массив объектов или `"UNKNOWN"` | Известные предшествующие работы с условиями связи. |
| `successor` | Массив объектов или `"UNKNOWN"` | Известные последующие работы с условиями связи. |
| `reference_ids` | Массив строк | Идентификаторы источников из корневого `references`. |

`source.context` — названия разделов исходной таблицы. Это не ссылки на родительские карточки и не технологический порядок. Некоторые работы находятся в нетипичных разделах источника, поэтому `macro_stage` может быть определен по смыслу названия, а не по заголовку раздела.

Категории `macro_stage` также не образуют календарную последовательность. Полный список и расшифровки находятся в самом JSON, в `macro_stage_definitions`.

## Наблюдаемость внешней камерой

Сценарий оценки — обычная наружная обзорная камера с последовательностью кадров, без доступа в помещения и тоннели и без специального приближения. Предполагается, что нужный участок попадает в кадр. Парапеты, глубина котлована, стены и другие перекрытия обзора снижают фактическую видимость.

| Оценка | Интерпретация по политике разметки |
| ---: | --- |
| 0 | Нет обоснованных прямых признаков для принятого наружного наблюдения. |
| 0.25 | Работа слабо различима; нужны подходящий ракурс или разрешение. |
| 0.5 | Видна часть процесса, но признаки неспецифичны или многое скрыто. |
| 0.75 | Характерные действия обычно различимы при открытом обзоре. |
| 1 | Процесс прямо и однозначно виден в принятом сценарии. |

Фактические значения в текущем файле лежат от `0` до `0.95`. Оценка обозначена как `HEURISTIC_NOT_CALIBRATED_PROBABILITY`: значение `0.85` не означает 85% вероятности выполнения работы, 85% готовности или точности модели.

Ноль может означать как скрытый процесс, так и отсутствие обоснованного правила распознавания неизвестной технологии. Например, у `work_169` («Трансбарьер») технология не раскрыта, поэтому следует читать `observability_note`, а не делать вывод о физической невидимости работы при любом ракурсе.

Наличие машины, доставка материала или отсутствие видимого действия сами по себе не подтверждают и не опровергают выполнение работы. Визуальные признаки также не устанавливают прочность бетона, герметичность, точный состав материала или работоспособность инженерной системы.

## Техника и неопределенность

В перечнях техники учитываются строительные машины, механизированные инструменты, измерительное и технологическое оборудование. Материалы, опалубка, леса, СИЗ и полный комплект ручного инструмента не перечисляются. Оборудование, которое устанавливают, не следует автоматически считать средством его монтажа.

| Поле и значение | Как трактовать |
| --- | --- |
| `required_equipment: ["Буровая установка"]` | Для определенной по названию технологии указан обязательный функциональный тип оборудования. |
| `required_equipment: []` | Универсально обязательная машина не выявлена; возможны варианты с ручным выполнением. Это не разрешение выполнять любую работу без техники. |
| `required_equipment: "UNKNOWN"` | Из названия и контекста нельзя установить обязательный комплект. |
| `optional_equipment: [...]` | Возможные средства, в том числе альтернативные. Все перечисленные машины одновременно не требуются. |
| `positive_visual_signs: []` | Надежные прямые признаки для наружной камеры не сформулированы. |
| `predecessor: "UNKNOWN"` или `successor: "UNKNOWN"` | Связь с конкретной строкой не установлена; это не доказательство отсутствия зависимостей. |
| `macro_stage: "UNKNOWN"` | Категория процесса не определена. |
| `reference_ids: []` | Для карточки не указан внешний справочный источник. |

`"UNKNOWN"` — строковый маркер, а не `null`, пустой список или отдельный идентификатор работы. Перед перебором `required_equipment`, `predecessor` и `successor` необходимо проверить тип или этот маркер. В текущем файле обязательная техника неизвестна у 167 карточек, список пуст у 198 и непуст у 12.

## Зависимости между работами

Каждая известная связь содержит четыре поля:

| Поле связи | Смысл |
| --- | --- |
| `work_id` | Идентификатор связанной карточки. |
| `condition` | Условие, при котором связь применима. |
| `basis` | Основание вывода; в текущем файле `EXPERT_INFERENCE`. |
| `scope` | Область применения; `SAME_ELEMENT_OR_WORK_AREA` — тот же элемент или участок, конкретизация дана в `condition`. |

Например, `predecessor` карточки `work_081` содержит:

```json
[
  {
    "work_id": "work_080",
    "condition": "Для одного участка нижнего слоя основания: материал уложен до его окончательной планировки.",
    "basis": "EXPERT_INFERENCE",
    "scope": "SAME_ELEMENT_OR_WORK_AREA"
  }
]
```

Для одного участка это дает цепочку: `work_080` — укладка нижнего слоя → `work_081` — планировка → `work_082` — уплотнение. На разных участках операции могут идти параллельно.

Связь отражена с двух сторон: в `successor` предшествующей карточки и в `predecessor` последующей. Поэтому 36 направленных связей представлены 72 записями в этих массивах. Чтобы построить граф без двойного учета, достаточно читать `successor` каждой карточки.

Граф неполный. Он не описывает все промежуточные операции, проверки и согласования. Условия могут относиться к партии оборудования, отдельному элементу или альтернативному варианту отделки. Нельзя автоматически требовать выполнения всех перечисленных строк на одном объекте или считать любую связь требованием закончить всю работу на всей площадке.

## Пример чтения на Python

Пример использует только стандартную библиотеку. Запускайте из корня репозитория; при другом рабочем каталоге измените путь к JSON.

```python
import json
from pathlib import Path

path = Path("rnd/store/construction_work_cards.json")
data = json.loads(path.read_text(encoding="utf-8"))
cards = data["cards"]
by_id = {card["id"]: card for card in cards}
references_by_id = {ref["id"]: ref for ref in data["references"]}

# Найти конкретную карточку и расшифровать категорию.
card = by_id["work_081"]
print(card["work_name"])
print(data["macro_stage_definitions"][card["macro_stage"]])

# Отобрать отдельные пункты с достаточно высокой оценкой наблюдаемости.
# 0.75 — иллюстративный фильтр, а не проверенный порог распознавания.
visible_items = [
    item for item in cards
    if item["row_kind"] == "ITEM"
    and item["external_camera_observability"] >= 0.75
]
print(len(visible_items))  # 126 в текущем файле.

# Прочитать зависимости, сохранив отличие UNKNOWN от списка.
predecessors = card["predecessor"]
if predecessors == "UNKNOWN":
    print("Предшественники не установлены")
else:
    for link in predecessors:
        previous = by_id[link["work_id"]]
        print(previous["id"], previous["work_name"], link["condition"])

# Разрешить справочные ссылки карточки.
for reference_id in card["reference_ids"]:
    reference = references_by_id[reference_id]
    print(reference["title"], reference["url"])
```

## Использование в анализе стройки

Справочник можно использовать для отбора наблюдаемых работ, поиска по технологическим категориям и подготовки описаний признаков для модели или разметчика. При этом:

- Передавайте вместе с названием `source.context`, визуальными признаками и оценкой также `observability_note`; ограничения часто меняют интерпретацию.
- Не объединяйте карточки только по одинаковому названию. Например, черновая отделка встречается в разных зонах и разделах.
- Отдельно учитывайте `AGGREGATE`, чтобы не считать общий раздел и его операции независимыми выполненными работами.
- Сохраняйте `condition` при использовании зависимостей и не превращайте `UNKNOWN` в отрицательное утверждение.
- Для применения численных оценок как вероятностей нужна отдельная проверка на видеоданных. Файл не содержит размеченных кадров, измеренной точности или привязки работ ко времени.

При изменении состава JSON обновите сводные числа и ожидаемый результат примера в этом README. Семантика полей и допущения хранятся в `annotation_policy` самого файла.

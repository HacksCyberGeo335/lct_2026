# Объекты и графики: подготовка frontend к API

Реализация от 29.09.2026, только frontend в main. Серверного API ещё нет.
Локального реестра нет: новая функциональность не пишет в localStorage,
sessionStorage или IndexedDB. Примеры из demo не добавляются.

## Что доступно сейчас

В разделе «Объекты» и на странице графика есть блок
«Объекты и графики работ». Два сценария:

1. «Добавить объект»: карточка объекта, затем необязательный график с ручными
   этапами или импортом CSV.
2. «Создать график работ» / «Импорт CSV графика»: выбор существующего объекта
   (когда появится API) либо создание новой карточки, затем подготовка графика.

Обязательные поля объекта: название, адрес строительства, застройщик/заказчик.
Дополнительные: округ/район, разрешение на строительство, тип/программа,
генподрядчик, ответственный/контакты, примечания.

Один объект содержит один календарный график. Его можно назвать, заменить CSV,
изменить вручную или удалить. Этап содержит название, сроки, зону, родительский
этап, потребность в технике; дополнительно можно задать правило проверки и связь
со справочником работ. Проверяются даты, ресурсы, вложенность, циклы, уникальные
ID и периоды подэтапов. Лимит CSV: 2 МБ / 2000 этапов, UTF-8.

Удаление родительского этапа затрагивает подэтапы и требует подтверждения с их
количеством. Удаление графика оставляет объект. Изменения графика и удаление
этапов применяются только к черновику формы, пока пользователь не сохранит объект.
Удаление серверного объекта имеет отдельное подтверждение и серверную операцию.

Пока API не подключён, кнопка серверного сохранения отключена. Черновик живёт
только в React-состоянии открытой формы. Закрытие формы, переход с неё или
перезагрузка его сбрасывают. Успешное создание/удаление объекта не имитируется.
Импорт CSV сообщает о переносе в черновик, а не о сохранении.

## Точка подключения

`src/features/projects/repository.ts` определяет `ProjectRepository` и
`projectRepository`. Сейчас `available: false`, методы завершаются понятной
ошибкой; UI их не вызывает. URL эндпоинтов не выдуманы.

Это внутренний интерфейс frontend, а не утверждённая спецификация backend:

- `list(signal)` возвращает `ManagedProject[]`; чтение поддерживает отмену.
- `create(fields, plan)` создаёт объект с необязательным графиком и возвращает
  сохранённый объект с серверным ID/версией.
- `update(original, fields, plan)` обновляет объект и его график; `plan: null`
  означает удаление графика. `original.version` нужен для защиты от потери
  изменений при одновременном редактировании.
- `remove(original)` удаляет объект вместе с графиком и этапами. Фото/видео
  отдельно не удаляются; поведение нужно подтвердить серверным контрактом.

После согласования контрактов реализовать HTTP-адаптер: URL, авторизация,
проверка DTO, сопоставление серверной модели и версии, таймауты и ошибки.
Для create/update требуется атомарная операция объекта с графиком либо явно
согласованная обработка частичных успехов. Для create нужен механизм
идемпотентности; нельзя автоматически повторять создание при неизвестном исходе.
После реализации всех методов включить `available`.

UI уже ожидает серверного завершения перед сообщением об успехе. Ошибка оставляет
черновик или диалог удаления открытым. Повторные клики во время операции блокируются.
После успеха инвалидируются запросы `['api', 'managed-projects']` и
`['api', 'objects']`. Для объектного удаления сервер должен соблюдать проверку версии.

`src/api/source.ts` переводит результат этого же адаптера в существующий интерфейс
навигации и проверки снимков: ID, название, график. Нейтральные поля совместимости
не являются аналитикой или измеренным прогрессом. При подключённом API график
передаётся в проверку снимков через `Project.stages`; временный план проверки
по-прежнему отдельный от календаря объекта.

## Файлы

- `ObjectWorkspace.tsx`: список, выбор адресата графика, карточки, мастер подготовки,
  серверное сохранение и удаление.
- `ProjectForm.tsx`: поля и проверка объекта.
- `PlanEditor.tsx`: черновик графика, таблица, импорт, редактирование и удаления.
- `StageForm.tsx`: поля этапа, техника, связь с родителем/справочником.
- `model.ts`: схема полей, вычисление ветви подэтапов.
- `ImportPlan.tsx`: общий CSV-парсер и предпросмотр, контекст черновика объекта.

Браузерные проверки проходят оба сценария, ручную валидацию, CSV, каскадное удаление
и отсутствие записи в localStorage / серверных запросов при выключенном адаптере.
Тестовый адаптер используется только в тестах для выбора существующего объекта,
отложенного сохранения графика и ошибок серверного удаления.

# Снимки и результаты анализа: frontend v1

Это формат **локального JSON-импорта**, реализованный во frontend ветки
`core-back-pipe`. Он не является опубликованным API backend. В этой ветке есть
загрузка видео, но нет серверного API снимков, распознавания и результатов.
Frontend не запускает ML и не создаёт детекции для пользовательских файлов.

## Проверка своего снимка

1. Откройте «Снимки и отклонения». Добавьте PNG, JPEG или WebP.
2. Импортируйте CSV-план с зонами и требованиями к технике или используйте календарь объекта.
3. Нажмите «Скачать шаблон результата». Блок `image` уже содержит имя,
   SHA-256 исходных байтов и размеры изображения.
4. Передайте файл и шаблон разработчику распознавания. В шаблоне нужно заменить
   время, камеру, зону, модель, качество, состояние и детекции фактическими данными.
5. Выберите готовый JSON в «Импортировать результат анализа (JSON)».
   Проверьте сведения в диалоге и нажмите «Применить результат».

Изображения, импортированные результаты и отдельный план проверки хранятся в памяти
вкладки, отдельно по выбранным объектам. Перезагрузка, смена режима и сброс настроек
очищают их. Переход между разделами сохраняет сеанс. Для сохранения результата
используйте «Скачать текущий результат»; исходный снимок остаётся на вашем диске.

Календарь demo-объекта хранится отдельно в localStorage. Импорт плана на странице
снимков меняет только текущую проверку. Переход из карточки календарного этапа
явно использует календарный план объекта, даже если в проверке открыт другой план.

## JSON

Полностью готовый синтетический пример:
[pit-missing.png.json](public/inspection/pit-missing.png.json), соответствующий
[pit-missing.png](public/inspection/pit-missing.png).

```json
{
  "version": 1,
  "image": {
    "name": "camera-01.png",
    "sha256": "64 шестнадцатеричных символа из скачанного шаблона",
    "width": 1920,
    "height": 1080
  },
  "captured_at": "2026-08-25T14:19:22+03:00",
  "camera_id": "camera-01",
  "zone": "А",
  "state": "succeeded",
  "model": "название и версия модели",
  "quality": { "usable": true, "reason": "" },
  "error": null,
  "detections": [
    {
      "id": "detection-1",
      "class_id": "exc",
      "confidence": 0.97,
      "bbox": [0.1, 0.2, 0.3, 0.4]
    }
  ]
}
```

В образце выше `sha256` — поясняющая заглушка; для импорта используйте хеш
реального файла или полный пример по ссылке. Все показанные поля обязательны.

| Поле                         | Правило                                                                               |
| ---------------------------- | ------------------------------------------------------------------------------------- |
| `version`                    | Число `1`                                                                             |
| `image.name`                 | Точное имя выбранного файла, 1–255 символов                                           |
| `image.sha256`               | SHA-256 исходных байтов, 64 hex-символа, регистр не важен                             |
| `image.width/height`         | Целые 1–20000, совпадают с декодированным снимком                                     |
| `captured_at`                | Время съёмки ISO 8601 с `Z` или смещением; календарно корректная дата                 |
| `camera_id`, `zone`, `model` | Непустые строки до 120 символов; внешние пробелы удаляются                            |
| `state`                      | `waiting`, `running`, `succeeded` или `failed`                                        |
| `quality.usable`             | Пригодность кадра для вывода, передаётся производителем результата                    |
| `quality.reason`             | До 500 символов; обязательное объяснение при `usable=false`                           |
| `error`                      | `null` либо строка до 500 символов; причина обязательна при `failed`                  |
| `detections`                 | До 2000 объектов; при незавершённом/ошибочном анализе только пустой массив            |
| `detections[].id`            | Уникальная в пределах снимка строка, 1–100 символов                                   |
| `class_id`                   | Строка 1–80 символов; неизвестные классы отображаются, но не дают достоверного вывода |
| `confidence`                 | Число от 0 до 1                                                                       |
| `bbox`                       | `[x, y, width, height]`, нормализовано к исходному снимку, начало слева сверху        |

Ширина и высота рамки положительны; рамка должна целиком помещаться в снимке.
Координаты относятся к изображению в его отображаемой ориентации, включая EXIF,
без полей/масштабирования, добавленных препроцессингом ML. Такие преобразования
производитель результата должен обратить перед экспортом.

Имя, хеш и размеры защищают от случайной привязки результата к другому файлу.
Они не подтверждают достоверность распознавания, времени и зоны: эти сведения
поступают от производителя JSON. Файл до 4 МБ, UTF-8. Дополнительные поля
игнорируются текущим парсером; текст отображается как текст, без выполнения HTML.

Изображение: до 20 МБ, до 40 мегапикселей, сторона до 20000 px.
В сеансе одного объекта максимум 50 снимков / 200 МБ исходных файлов.
Повреждённый или повторяющийся по хешу файл отклоняет всю выбранную пачку.
Для локального SHA-256 браузеру нужен HTTPS или localhost.

## Классы

| ID frontend    | Название                                            |
| -------------- | --------------------------------------------------- |
| `dump`         | Самосвал                                            |
| `exc`          | Экскаватор                                          |
| `roller`       | Каток                                               |
| `manipulator`  | Кран-манипулятор                                    |
| `mixer`        | Бетоносмеситель                                     |
| `dozer`        | Бульдозер                                           |
| `truck`        | Грузовик                                            |
| `mobile_crane` | Автокран                                            |
| `crane`        | Общий класс «Кран», сохранён для прежних демоданных |

Числовые индексы классов датасета не предполагаются. Производитель результата
должен явно сопоставить свои метки с этими ID. `crane`, `mobile_crane` и
`manipulator` не считаются взаимозаменяемыми автоматически.

## Правила сопоставления

1. Берутся конечные этапы плана, активные на **московскую дату** снимка
   (границы включены) и имеющие ту же зону. Сравнение зоны игнорирует регистр
   и внешние пробелы; латинская A и кириллическая А — разные зоны.
2. Состояние должно быть `succeeded`, кадр — пригодным. Незавершённый анализ,
   ошибка, плохое качество, неизвестный класс или любая детекция с уверенностью
   ниже **0,5** дают «Недостаточно наблюдений».
3. Каждое требование `класс → минимальное количество` проверяется отдельно.
   Недостающее количество даёт объяснение: какой класс, сколько ожидалось и найдено.
   Пустой массив при успешном качественном анализе означает наблюдаемый ноль.
4. `required-and-unexpected` также ищет классы вне объединения требований
   **всех активных этапов той же зоны**. Для `required-only` эта проверка выключена.
   Если у параллельного этапа нет правила, допустимость полного набора неизвестна,
   поэтому строгий результат остаётся недостаточным.
5. Этап без требований не становится успешным. Сводные этапы не проверяются
   повторно вместе с подэтапами. Машины не суммируются между снимками.

Количество сравнивается с каждым этапом отдельно; распределение одной машины
между параллельными работами не моделируется. Правило описывает наблюдение
в конкретном кадре, а не отсутствие машин вне обзора и не физический процент
готовности строительства. Предупреждение содержит этап, зону, дату и именно
тот снимок, по которому выполнен расчёт.

## Будущая серверная интеграция

Валидация отделена от транспорта:
`src/api/analysisResult.ts::parseAnalysisResult(value, frame)`.
После появления согласованного API его ответы можно передавать этому парсеру.
Потребуются реальные серверные операции загрузки снимка, получения состояния
и результата, привязки к объекту/камере, хранения планов и результатов.
Endpoint'ы, авторизация, polling и запуск ML в этой правке не выдумываются.

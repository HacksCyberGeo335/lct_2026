# Проверка и рефакторинг frontend · 26.09.2026

Область: `prom_app/frontend`, ветка `core-back-pipe`. Проверены маршруты, загрузка видео,
проверка снимков в обоих режимах, импорт, хранение профилей, календарь, аналитика,
состояния ошибок и клавиатурная навигация. Backend и Dockerfile не изменялись.
Стиль, маршруты, старый ресурсный режим и формат результатов распознавания v1 сохранены.

| Подтверждение обзора сохранялось после смены зоны, работы или этапа | Общий переход профиля сбрасывает обзор при изменении работы, этапа, источника плана, зоны, камеры или плановых дат. | Ручная работа могла переноситься в другую строку календаря без привязки к справочнику | В новой строке без `work_id` работу нужно выбрать явно; ручной выбор для той же строки сохраняется | Unit: переход между несвязанными строками |
| Надпись «Профиль сохранён» оставалась после редактирования | Сообщение привязано к снимку настроек на момент сохранения/применения | Playwright: сохранение и изменение зоны |
| Ошибка повреждённого сохранённого профиля не исчезала после успешного восстановления | Уведомление убирается после успешной записи нового профиля в браузер | Playwright: повреждённый JSON → сохранение |
| Валидный CSV отклонял одинаковые подэтапы у разных родителей | Проверка смысловых дублей учитывает `parent_id`; повтор ID и дубль внутри одного родителя по-прежнему отклоняются | Unit: валидная иерархия и оба вида дублей |
| После асинхронного импорта JSON закрытие диалога возвращало фокус в начало страницы | Диалог получает явную ссылку на поле импорта; общий механизм проверяет возврат фокуса и использует `main` как запасной вариант | Playwright: Escape и применение результата в обоих режимах |
| Выбор работы сбрасывал поиск/фильтры и терял клавиатурный фокус | Убрано перемонтирование всего списка. Состояние раскрытия отделено от фильтров, фокус возвращается на заголовок списка | Playwright: выбор клавиатурой и повторное раскрытие |
| Смена периода аналитики удаляла переключатель на время загрузки | Панель отчёта остаётся на месте; загрузка/ошибка заменяет только содержимое. Печать недоступна до получения данных | Playwright: фокус до и после загрузки нового периода |
| Зависшая загрузка справочника или демонабора оставляла вечное ожидание | Каждый запрос использует общий транспорт с пределом 20 секунд, включая чтение тела ответа, и отменой при уходе | Unit: ожидание заголовков, JSON и файлов справочника, отмена |

Импорт профиля также принимает расширение `.JSON` без учёта регистра и строго проверяет UTF-8.

## Рефакторинг

- `domain/profileTransitions.ts`: правила редактирования и привязки профиля к этапу вынесены из компонентов. Валидированный импорт и явное открытие демо остаются отдельными действиями.
- `features/inspection/useFileOperation.ts`: общий жизненный цикл файловых операций для справочника и ресурсного режима — блокировка повторного запуска, ошибки, отмена транспорта, защита от запоздалого результата после ухода со страницы.
- `api/analysisResult.ts`: единое формирование шаблона результата, чтобы два режима не расходились в контракте.
- `api/http.ts`: загрузка статических JSON использует существующую обработку тайм-аутов с сообщениями для файлов приложения.

## Результаты проверки

Все команды завершились успешно:

- `npm run lint`;
- `npm test`: **73 теста**, 12 файлов;
- `npm run build`, включая TypeScript;
- `npm run test:e2e`: **51 тест**, включая 6 новых браузерных регрессий;
- `node tools/verify-preview.mjs`: production preview, маршруты, видео, справочник, пример снимков, начальный API-режим и ошибка неизвестного режима.

Полный E2E-набор также проверяет загрузку и воспроизведение видео, поиск и фильтры,
CSV, хранение настроек, геометрию детекций, печать, узкие экраны, reduced motion,
порядок API-загрузки и повтор подтверждения без повторного PUT.

Проверки API-транспорта выполняются с подменёнными ответами. Живой Gateway/MinIO/ML
этим прогоном не проверялся. Во время проверки preview отсутствие локального Gateway
на порту 8080 дало ожидаемую ошибку соединения; интерфейс сохранил API-режим.
Docker-контейнер и nginx отдельно в этом прогоне не запускались; их конфигурации не менялись.

## Границы готовности

Фронт поддерживает локальные снимки, импорт результатов, работу со справочником,
ручные условия проверки, объяснение результата и существующий контракт загрузки видео.
API анализа снимков и полноценный ML-конвейер требуют backend. Автоматические тревоги
об отсутствии техники по справочнику остаются выключены; снимки и синтетическое демо
не выдаются за результат реальной серверной проверки.

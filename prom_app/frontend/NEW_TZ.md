# Исправления frontend по новому ТЗ

Основание: «7. Департамент градостроительной политики города Москвы.pdf»,
предыдущий аудит frontend от 15.09.2026. Ветка: `core-back-pipe`.
Изменения ограничены `prom_app/frontend`; Dockerfile сохранён.

| Пункт аудита                         | Что реализовано                                                                                                                    | Что ещё зависит от backend / ML                                                   |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| F1: только видео и SVG               | Раздел «Снимки и отклонения», реальные PNG/JPEG/WebP, пачка файлов, просмотр исходных пропорций, рамки по геометрии снимка         | Получение снимков с камер и серверное хранение                                    |
| F2: нет приёма результатов           | Проверяемый JSON v1, импорт с preview, привязка по SHA-256/имени/размерам, состояния анализа, общий парсер для будущего транспорта | Живой API результатов и распознавание; локальный импорт не заменяет их            |
| F3: один ресурс у этапа              | Массив требований к нескольким классам, CSV `resources`, явная политика правила, совместимость со старым CSV                       | Выдача и сохранение серверных планов                                              |
| F4: проценты вместо проверки техники | Отдельное сопоставление снимка с правилами: нехватка, несоответствующий класс, норма, недостаток данных                            | Качество распознавания, охват камеры и согласование правил предметными экспертами |
| F5: неподходящий кадр-основание      | Связь снимок → московская дата → зона → активный этап; ссылки открывают точное изображение и нужный план                           | Достоверные метаданные времени/камеры/зоны                                        |
| F6: четыре класса                    | Восемь предметных классов ТЗ, прежний общий кран; неизвестные классы отображаются безопасно                                        | Согласованное сопоставление ID классов конкретной модели                          |
| F7: потеря иерархии                  | `parent_id`, проверка родителей/циклов/периодов, дерево в календаре и плане; сводные этапы исключены из повторного расчёта         | Экспорт исходного графика в согласованный CSV                                     |

Старый график процентов остаётся явно обозначенной модельной демонстрацией.
Демонстрационные риски по календарю не выдаются за результат проверки техники.
Пользовательским файлам не назначаются синтетические детекции.

## Воспроизводимый сценарий

`npm ci`, `npm run dev`, затем
http://127.0.0.1:5173/objects/north-park/inspection?mode=demo.
Нажмите **«Загрузить пример ТЗ»**.

- `pit-missing.png`: экскаватор есть, не хватает двух самосвалов.
- `pit-unexpected.png`: не хватает самосвала и найден кран вне требований котлована.
- `pit-ok.png`: экскаватор и два самосвала, требования выполнены.
- `foundation-ok.png`: другая зона и соответствующий ей этап фундамента.
- Опция показа остальных этапов объясняет другую зону и неактивный период.

Все четыре изображения и результата синтетические; пример загружается только
по явному действию. Для собственного изображения нужен результат распознавания
в формате [ANALYSIS_CONTRACT.md](ANALYSIS_CONTRACT.md).

## Проверки

В автоматические проверки входят сравнение наборов техники, обе причины
предупреждения, низкая уверенность и неизвестные классы, некорректные JSON/CSV,
неверная привязка к файлу, даты и иерархия, локальный режим без HTTP-загрузки,
переход к конкретному доказательству, геометрия PNG/JPEG/WebP и узкие экраны.
Команды и актуальное количество тестов — в [README.md](README.md).

Полная система по ТЗ ещё требует серверной обработки и ML. Точность модели,
нагрузка анализа и работа живых камер этими frontend-тестами не подтверждаются.
Презентация, проектная документация и рекомендации по установке камер остаются
отдельными командными материалами. ТЗ допускает CSV **или** Excel; XLSX в этой
правке не добавлен.

# Стройконтроль · frontend

Рабочая версия использует существующие Gateway и Upload Service. Backend сейчас
поддерживает проверку доступности Gateway и сохранение файлов в MinIO с подтверждением
в PostgreSQL. Реестра объектов, камер, календарных планов и анализа пока нет.

Отчёт о базовой интеграции от 27.09.2026: [INTEGRATION_REPORT.md](INTEGRATION_REPORT.md).
Изменения загрузки от 29.09.2026 описаны ниже в этом README.
Предыдущие REVIEW/NEW_TZ/FRONTEND_REVIEW и документы в `docs/` описывают прежние этапы проекта.

## Main и demo

- `main`: режим API по умолчанию и в разработке, и в production. Нет демофотографий,
  готовых результатов, искусственных объектов и переключателя демо. `?mode=demo`
  не включает демо; `VITE_APP_MODE=demo` вызывает понятную ошибку конфигурации.
- `demo`: тот же рабочий код плюс `src/demo/entry.ts`, данные, демонстрационные страницы
  и public-материалы. В dev демо выбирается по умолчанию, если `VITE_APP_MODE` не задан.
  В production демо открывается явно через `?mode=demo` или переключатель.
- `src/app/demoExtension.ts` — общий контракт дополнения. Наличие файла дополнения
  определяется при сборке. Одной переменной окружения нельзя вернуть демо в `main`.
- Общую логику меняйте в `main`, затем переносите изменения в `demo` слиянием `main → demo`.
  Не сливайте демонстрационные дополнения обратно в `main`.

Изменения оформлены отдельными коммитами: рабочая версия в `main`, демонстрационное
дополнение поверх неё в `demo`. Обновление форматов загрузки от 29.09.2026 выполняется только в `main`; `demo` остаётся на предыдущей версии.

## Запуск рабочей версии в Windows / PowerShell

Нужен Node.js 20.19+ или 22.12+ и npm. Docker Desktop нужен только для backend-стека.

Из корня репозитория поднимите существующие сервисы:

```powershell
docker compose up -d --build postgres s3-storage s3_init upload_service api_gateway
```

Запустите frontend:

```powershell
cd prom_app/frontend
npm.cmd ci
npm.cmd run dev
```

Откройте `http://127.0.0.1:5173/objects`. Без backend интерфейс запустится и покажет
ошибку подключения. Это не демонстрационный режим и не успешная загрузка.

По умолчанию Vite проксирует `/api` и `/health` на `http://127.0.0.1:8080`.
Для других адресов создайте `.env.local` по примеру `.env.example`:

```dotenv
VITE_APP_MODE=api
VITE_API_BASE_URL=/api
API_PROXY_TARGET=http://127.0.0.1:8080
```

Если в старом `.env`/`.env.local` стоит `VITE_APP_MODE=demo`, замените его на `api`
для рабочей ветки. После изменения переменных перезапустите Vite.

Полный существующий Compose с nginx-frontend:

```powershell
# Из корня репозитория
docker compose up -d --build postgres s3-storage s3_init upload_service api_gateway frontend
```

Frontend будет на `http://localhost:3000` при стандартных переменных. Compose передаёт
`VITE_API_BASE_URL=/api`; nginx проксирует запросы в Gateway.
`MINIO_PUBLIC_ENDPOINT` в корневом `.env` должен быть доступен именно браузеру.
Для другой машины `localhost:9000` обычно не подходит: задайте публичный адрес MinIO.

## Что можно проверить

1. Нажмите «Проверить подключение». Успешный `/health` подтверждает доступность только Gateway.
2. «Загрузить фото или видео» → выберите одно видео или несколько фото → «Загрузить файлы».
3. Дождитесь READY и UUID. Порядок: `init-upload`, PUT файла, `upload-complete`.
4. «Перейти к файлам» открывает фото или видео из MinIO. Ошибка просмотра не отменяет READY;
   «Повторить просмотр» не загружает файл повторно.
5. При ошибке подтверждения «Повторить подтверждение» повторяет только последний POST.
   Список загруженных записей существует только до перезагрузки: API списка отсутствует.
6. В «Снимки и отклонения» можно локально открыть свои PNG/JPEG/WebP/BMP/AVIF, импортировать
   имеющийся JSON результата, выбрать работу и условия. В этом разделе снимки остаются локальными, ML не запускается.
   Для отправки оригиналов на сервер используйте загрузку в разделе «Объекты». Формат: [ANALYSIS_CONTRACT.md](ANALYSIS_CONTRACT.md).
7. CSV в проверке снимков задаёт локальный план сеанса. Предпросмотр плана в календаре
   не сохраняет его на сервер: соответствующий API пока отсутствует.

Справочник в `public/catalog` — поставленные справочные данные проекта, не fake-результаты
анализа. Копии синтетических файлов в `tests/fixtures` используются только тестами,
не попадают в `dist` и не раздаются по `/tests/` в dev/preview.

## Форматы и пакетная загрузка (main, 29.09.2026)

- Видео: MP4, AVI, MOV, MKV, WebM, M4V, MPG/MPEG, WMV, 3GP, MTS/M2TS, OGV.
  Одно видео за раз, до 2 ГБ.
- Фото: JPEG/JPG, PNG, WebP, GIF, BMP, AVIF, TIFF/TIF, HEIC/HEIF.
  До 50 фото за раз, каждое до 20 МБ, вся выбранная пачка до 200 МБ.
- Выбор нескольких фото и перетаскивание работают одинаково. Вся выбранная пачка
  проверяется до отправки. Неподдерживаемый файл или смесь видео с фото показывает
  ошибку; файлы не пропускаются молча. Проверяются расширение, MIME и размер;
  это не проверка содержимого/кодека и не антивирус.
- Файлы передаются последовательно с индивидуальным статусом и прогрессом.
  При ошибке/отмене очередь останавливается. Повтор пропускает успешные файлы;
  после успешного PUT повторяется только подтверждение. Закрытие диалога отменяет
  текущую передачу, повторное открытие сохраняет очередь в рамках этой страницы.
  Уход со страницы/перезагрузка теряет очередь; серверные объекты не удаляются.
- Существующий `/api/videos/init-upload` принимает имя и размер любого файла;
  PUT сохраняет оригинальные байты и Content-Type, `upload-complete` проверяет HEAD.
  Для фото используется этот же контракт, несмотря на историческое имя `/videos`.
  Backend и схема БД не менялись: тип файла определяется в UI по расширению и
  сохраняется в метаданных объекта как Content-Type. Новых API фото/анализа нет.
- Загрузка формата не гарантирует просмотр в браузере: особенно AVI/MKV, HEIC/TIFF.
  Фронт не конвертирует файлы. Ошибка просмотра не отменяет READY; доступны
  повтор просмотра и ссылка «Открыть оригинал». Для локальной проверки снимков
  используйте PNG/JPEG/WebP/BMP/AVIF; другие форматы предварительно экспортируйте.
- Список загруженного хранится в памяти вкладки. READY означает только сохранение,
  не результат анализа. Живая интеграция с MinIO требует запущенного backend;
  браузерные автотесты используют подмену HTTP только внутри тестов.

54 E2E, один main-only тест намеренно пропущен. Lint, TypeScript, build и preview
прошли в обоих checkout. API-ответы в обычных E2E подменяются только внутри тестов.

Отдельная проверка живого стека, **без подмены запросов**, при уже запущенных сервисах:

```powershell
$env:FRONTEND_URL='http://127.0.0.1:5173'
node tools/verify-live.mjs 'C:/path/to/video.mp4'
```

Эта команда реально загружает файл. Сохраните выведенный UUID: API удаления нет.

## Заготовка результата LLM (main, 29.09.2026)

После успешной загрузки под выбранным файлом появляется блок «Обработка и результат LLM»:
этапы загрузки, обработки и получения ответа, а также область будущего текста модели.
Сейчас он явно помечен «Заготовка интерфейса»: обработка не запускается, прогресс и
выводы модели не выдумываются. Для каждого выбранного фото/видео показано его имя.

`src/features/analysis/AnalysisPanel.tsx` отображает состояния `unavailable`, `queued`,
`processing`, `completed`, `failed`. `types.ts` задаёт только внутреннюю модель UI,
не договорённый серверный контракт. Будущий API-адаптер должен привязать ответ к UUID
файла (`fileId`) и обновлять `LocalRecording.analysis`. При несовпадении UUID ответ
не отображается. Текст модели выводится как обычный текст с сохранением переносов,
без выполнения HTML. Пока нет HTTP-запросов анализа, таймеров, симуляции очереди или
автоматического перехода к «Готово». Backend и ветка demo не изменены.

## Объекты и графики: интерфейс под будущий API

В «Объектах» доступны «Добавить объект», «Создать график работ» и «Импорт CSV графика».
Можно заполнить карточку, подготовить график вручную или из CSV, изменить и удалить
этапы/график в черновике. Выбор существующих объектов, серверное сохранение и удаление
подготовлены, но недоступны до подключения API. Локального реестра и сохранения
в браузерное хранилище нет. Черновик исчезает при закрытии формы или перезагрузке.

Подробности и точка подключения: [PROJECTS_API_HANDOFF.md](PROJECTS_API_HANDOFF.md).


## Мониторинг, настройки и пользовательский справочник

«Площадка» содержит загрузку и просмотр фото/видео, область результатов детекции
и сопоставление с графиком. До подключения анализа результаты не имитируются.
Редактор объектов находится в «Объектах», редактор графика — в «Графике работ».
В «Настройках» восстановлены оповещения и почтовые получатели. Пока нет API,
переключатели и адреса — черновик страницы; сохранение и отправка недоступны.

В «Снимках и отклонениях» можно использовать встроенный справочник, отредактировать
его копию или загрузить собственный JSON (до 8 МБ). Для подготовки файла скачайте
текущий справочник как шаблон: он содержит version, name, cards, equipment и durations.
Импорт проверяет схему, ссылки между работами и техникой и поддерживаемые классы
детектора. Некорректный файл не заменяет текущую версию.

Редактор копии позволяет менять название справочника, названия работ, визуальные
признаки и альтернативы техники в существующих требованиях. Структуру и новые
группы можно подготовить в JSON. Пользовательская версия действует в текущей
сессии приложения: экспортируйте её перед перезагрузкой и затем импортируйте снова.
Встроенный файл не перезаписывается. Профиль сопоставления привязан к содержимому
справочника; после изменений его нужно проверить заново.

Числовые экспертные оценки и внутренние идентификаторы убраны с основного экрана.
Условия, влияющие на требования к технике, сохранены в раскрывающемся блоке;
неуказанное условие не считается подтверждённым. Источники доступны в подробностях.

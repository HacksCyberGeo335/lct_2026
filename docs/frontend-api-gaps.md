# Frontend: действующие контракты и пробелы

Сверено 13.09.2026 с веткой `core-back-pipe`, исходный коммит `37479ed`.
Инструкции переписки в README рассматриваются как история. Worker, Triton, GPU,
очередь обработки и новые таблицы этой задачей не создавались.

## Карта функции → код → реализация

| Функция                     | Подтверждённый код/контракт                                                                | Реализация frontend                                                                       |
| --------------------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |

| Начало загрузки             | `upload_service/internal/handler/video.go`, POST /api/videos/init-upload, {file_name,size} | Zod DTO, ручной запуск, без автоматического повторения init                               |

## Расхождения исходных материалов с кодом

- В приложении MinIO-документ описывает ключ как uuid/filename; Go и API-Specification.md
  возвращают **bucket/uuid/basename**. Адаптер поддерживает оба варианта.
- READY — завершение загрузки и сохранение метаданных объекта, не успешный ML-анализ.
- Структура worker/Triton и состояния очереди в README — проектные предложения.
- Старый frontend не проверял DTO полностью, не отменял XHR и повторял весь flow после ошибки
  complete. Новый сохраняет ticket в рамках страницы и повторяет подтверждение отдельно.
- Старый nginx не проксировал API. Новый proxy обслуживает относительный /api,
  JSON-схема логов сохранена. Изменение документации API-Specification.md не выполнялось.
- Референс показывал архив как «В эфире», будущие фактические даты, общий статический Gantt,
  независимые несогласованные счётчики и условные рамки на пустом фоне.
  Реализация использует один срез, вычисляемые полосы, источник времени медиа,
  настоящие локальные синтетические ролики и честные подписи.
- Клиентские ограничения MP4/WebM/MOV и 2 ГБ — не ограничения сервера.
  Сервер не проверяет кодек/контейнер, а размер init не сверяет с результатом HEAD.

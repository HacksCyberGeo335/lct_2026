# Проверка frontend

Проверено локально на Windows 13.09.2026, Node.js 24.20.0, npm 11.19.0.
Целевая ветка: **core-back-pipe**. Dockerfile не изменён.

## Выполнено

- Отдельный TypeScript strict typecheck, ESLint, production build.
- **18 unit/integration-тестов** Vitest + Testing Library: DTO, публичные URL,
  кириллица/спецсимволы, init→PUT→complete, ошибки/отмена, повтор complete,
  CSV/ошибки строк, календарные даты, согласованность агрегатов, localStorage,
  восстановление фокуса диалога.
- **17 E2E Playwright Chromium**: все пять экранов, прямые URL/перезагрузка/история,
  поиск+статус+сортировка, сохранение фильтров, смена объекта, источники, синтетическое
  видео и seek, локальная загрузка без ML-результатов, состояния обработки/камер,
  импорт/отмена/ошибки/сохранение, настройки/перезагрузка/ошибка сохранения,
  reduced motion, focus trap, повторное открытие, API-ошибки без demo fallback.
  Режим данных следует Back/Forward; выбранный объект сохраняется при переходе через
  ведомость; быстрые изменения разных фильтров не стирают друг друга.
- Ширины **1440, 1280, 768, 390 px**: пять экранов, отсутствие общего горизонтального
  overflow; таблицы и Gantt прокручиваются внутри контейнера. Скриншоты сохранены локально.
- HTML-референс изучен в браузере по всем пяти экранам; перенесены исходные CSS-токены,
  геометрия ведомости, верхняя навигация, типографика, палитра, радиусы и статусы.
  Новые формы и контекст источника добавлены в тот же язык интерфейса.
  Скриншоты референса сняты на тех же четырёх ширинах для сравнения.
- Console/page errors и неуспешные сетевые запросы в основном demo-сценарии отсутствуют.
  Предупреждение Motion о включённом reduced motion в dev ожидаемо.
- Печатный PDF: объект «Речной квартал», 30 дней, кириллица, метка demo, дата формирования,
  график и все четыре строки таблицы. PDF отрендерен Poppler и осмотрен: **одна страница A4**.
- Production bundle проверен через **настоящий nginx 1.30.4 для Windows**:
  пять глубоких ссылок дают 200; /api — 404; недоступный upstream /api/videos/... — 502;
  отсутствующие /media и /assets — 404. Ни один из этих путей не получает SPA HTML.
  В production начальный режим api, явный ?mode=demo воспроизводит локальное видео 60 секунд.
- Для локальной nginx-проверки взят frontend nginx.conf; адаптированы только bind/порт
  (127.0.0.1:4180), filesystem root и вывод логов в файлы Windows. Docker DNS сохранён.
  Синтаксис nginx-конфигурации проверен командой nginx -t.
- **Vite preview**: все пять глубоких ссылок, явный demo и начальный api, перезагрузка,
  переход по логотипу и локальное видео. Отдельный Vite dev-сервер с неизвестным
  VITE_APP_MODE показал в браузере ошибку конфигурации без перехода в demo.
  Скрипт `tools/verify-preview.mjs` повторяет обе проверки.

## Честные ограничения проверки

- Docker в среде не установлен; контейнерная сборка Dockerfile и всего Compose не запускалась.
- Локальные Gateway :8080 и MinIO :9000 недоступны. **Живой upload в PostgreSQL/MinIO
  не проверен**. Тела запросов/ответов сверены с Go-кодом; HTTP-сценарии E2E используют mock routes.
- GPU, ML worker, очередь, processing API и реальная аналитика в репозитории не реализованы.
  Их отсутствие явно отражено интерфейсом и [таблицей пробелов](frontend-api-gaps.md).
- Браузерные проверки выполнялись в Chromium. Поведение кодеков и печати в других
  браузерах необходимо проверить отдельно перед rollout.

## Повторение

См. команды в [README frontend](../prom_app/frontend/README.md).
Скриншоты/PDF/JSON результатов остаются в локальном `prom_app/frontend/artifacts/`
и не добавляются в Git. Тесты и инструменты генерации/проверки входят в репозиторий.
Для воспроизводимой проверки живого сервера запустите существующий Compose, выберите
API, загрузите непустое видео и проверьте READY и HEAD/метаданные на стороне backend.
